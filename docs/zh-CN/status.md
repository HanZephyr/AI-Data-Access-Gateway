# 项目现状

[English Status](../en/status.md)

## 发布定位

AI Data Access Gateway 当前以 V1 MVP 形式开源发布。它面向本地试用、演示环境和持续中的开源协作，重点在于证明受治理的数据访问链路已经具备可运行的基础能力，而不是宣称当前仓库已经达到企业级生产平台成熟度。

## 当前已实现能力

### 后端

- 基于 FastAPI 的应用入口、配置系统、健康检查与控制平面数据库初始化
- Alembic 迁移链路，覆盖控制平面基础结构、目录运行时基线与近期安全加固变更
- API Key 生命周期与作用域校验，支持管理面与运行时访问
- FastMCP Streamable HTTP `/mcp` 端点，以及更简单的 `/api/tools/{tool_name}` HTTP 工具接口
- 关系型数据源注册、连接器注册表与元数据扫描
- 资源、字段、目录与脱敏配置的持久化模型

### 运行时与治理

- 只读查询守卫，阻止危险 SQL 执行路径
- 资源级、字段级访问检查与标签可见性控制
- 固定值、局部、哈希、可逆脱敏，以及运行时解密控制
- 审计日志记录，包括管理面与运行时关键事件

### 管理控制台

- React + Vite 管理控制台
- 面向单管理员信任模型的数据源、资源治理与审计工作流
- 管理员 API Key 仅保存在浏览器内存态中，不落地到本地持久化存储
- 数据源敏感凭据以占位形式返回，避免管理 API 直接回显明文

### 打包与演示流程

- `examples/seed_demo.py` 用于初始化演示数据和一次性管理员 API Key
- 管理 API 会暴露 `/mcp` Streamable HTTP 服务地址，以及 `/api/tools/{tool_name}` 工具接口模板
- `examples/mcp_client_http.py` 提供最小化的运行时 HTTP 调用示例
- `docker-compose.yml` 提供后端与静态前端的组合启动方式
- 后端、前端、前端生产依赖审计，以及基于导出依赖快照的 Python 审计命令已具备基本验证入口

## 已知限制

- 当前信任模型仍以单管理员为前提，没有独立的后台登录系统
- 运行时策略执行聚焦资源级与字段级控制，未覆盖行级过滤
- 仓库默认更偏向本地演示与评估场景，仍需额外补齐生产部署所需的 TLS、密钥管理、可观测性与运维防护
- 当前运行时与 MCP 接口直接运行在主 FastAPI 进程中，生产环境仍需要外围接入层与部署控制配合

## 当前 MVP 明确不包含的内容

- 企业级管理员身份体系、SSO、MFA 或多管理员协作 RBAC
- 自动化的行级权限裁剪与查询改写
- 内建的高可用部署模板、密钥轮换平台或完整零信任接入体系
- 面向广泛数据源生态的全面适配承诺
- 对企业级生产落地能力的当前承诺

## 近期加固优先项

- 完善开源发布文档、治理文件与双语导航
- 持续运行基于仓库已解析 Python 依赖图和前端生产依赖集合的 CI 与安全审计自动化
- 继续强化管理员认证模型、部署安全姿态与运维可观测性
