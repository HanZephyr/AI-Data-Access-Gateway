# 安全策略

[English original](../../SECURITY.md)

## 支持版本

AI Data Access Gateway 当前以 MVP 形式发布。安全修复预期会优先落在最新的主线版本上，较旧的快照、分叉仓库、实验性分支以及无人维护的修订版本，不应被默认视为会收到回补修复。

## 报告安全漏洞

请不要通过公开的 GitHub Issue 报告疑似安全漏洞。

请通过仓库维护者提供的私下联系渠道报告安全问题；如果仓库启用了私有安全公告报告能力，或后续配置了专用安全邮箱，也应优先使用这些渠道。

报告漏洞时，请尽量包含以下信息：

- 受影响的版本、分支或提交
- 部署环境或运行时上下文
- 清晰的复现步骤或概念验证
- 预期影响以及受影响的信任边界
- 任何可行的缓解措施或补偿性控制建议

维护者会审查报告内容，确认问题是否属于仓库范围，并根据当前可用维护能力谨慎协调披露流程。对于一个 MVP 仓库，响应时间可能会有所波动，但维护者会本着善意对报告进行分诊处理。

## 范围说明

本仓库是一个开源 MVP。若报告能证明以下领域存在实际影响，会特别有帮助：

- 认证或授权绕过
- 密钥、凭据或敏感数据泄露
- 脱敏或运行时解密控制绕过
- SQL Guard 绕过并导致进入被禁止的执行路径
- 管理面或运行时 API 暴露缺陷
- 实质性削弱安全审查可追溯性的审计日志缺口

除非能够证明问题依赖于本仓库中的可复现缺陷，否则以下情况通常不在当前范围内：

- 仅存在于不受支持分叉或经过大幅下游修改部署中的漏洞
- 需要本地特权 Shell 访问且不涉及网关自身缺陷的报告
- 没有可复现仓库影响的纯理论性问题
- 完全依赖仓库默认值之外的不安全运维配置才成立的发现

## 协调披露

在维护者有合理机会验证问题并准备修复或缓解措施之前，请避免公开披露相关细节。如果某个报告被判定为超出范围，或无法复现，维护者可以在不继续推进的情况下关闭该报告。
